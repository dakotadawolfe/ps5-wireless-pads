# PS5 13.60 and Xbox Elite Series 2

## Status

Experimental candidate, not console-verified. No payload was sent to the user's
console during development. Pairing, input, rumble, virtual-user assignment and
rest-mode survival on 13.60 remain unverified.

Base: AngelLopezTorres/ps5-wireless-pads commit
`33fa2fe` (0.2.0-beta). Controller target: Xbox Elite Series 2. Its BLE profile is
`045e:0b22`; older controller firmware may use Classic IDs `045e:0b00/0b05`.

## Findings and changes

1. **Startup failure: concrete missing import.** The 13.60 report identifies
   `sceAppInstUtilAppInstallTitleDir` as absent. Upstream imports it directly,
   preventing ELF startup before `main`, including when `no_icon` is present.
   This fork resolves it dynamically and skips launcher creation if unavailable.
   Credit: Nicolas8aa's issue and commit `2bccc2e` identified this repair.

2. **USB event delivery: candidate radio-path repair.** Upstream submits event
   reads of `wMaxPacketSize` (16 bytes in the captured descriptor). Large events
   are split into separately queued reads beside Sony's reader. The fork uses
   260-byte event reads, with short transfers allowed, so USB can collect the
   whole event. Linux btusb makes the same distinction between endpoint packet
   size and maximum HCI event length. This reduces a source of fragment loss;
   only a hardware trace can establish whether it explains 13.60's silence.
   It does not grant exclusive ownership or guarantee no event loss.

3. **False scan state and repeated enables: source-confirmed bugs.** Previously,
   submitting a command marked the scan active even on refusal. A confirmed
   scan was also re-enabled every five seconds. The new state follows successful
   acknowledgements, retries failures/lost replies with a delay, and stops its
   potentially active scan on shutdown. A Command Disallowed response is not
   treated as proof that scanning works.

4. **Discovery filtering: source-confirmed omissions.** Previously only the first
   report in an LE Advertising Report event was examined. Scan responses were
   ignored, even though the code deliberately requested active scanning for names.
   The new parser iterates bounded records and joins data from a connectable
   advertisement and a matching recent scan response. It checks address type,
   expires entries after five seconds, ignores unsolicited responses, and removes
   zero padding before joining AD fields.

5. **Classic/LE overlap: experimental isolation.** This build defaults to LE-only
   discovery for current Xbox firmware. `classic_discovery=1` restores inquiry
   for older Classic controllers. The published 13.60 test already tried LE-only
   scanning without success, so this setting alone is not a claimed fix.

6. **Visibility:** setup logs local LE feature bits and host support without
   changing the latter. Rejected scan parameters disable LE discovery. During a
   scan, logs include acknowledgements and report counts; zero reports trigger
   transport diagnostics, including fragmentation and the selected interface.

## What this does not resolve yet

The known test on 13.60 received no LE advertisements from HCI function 0 after
the startup fix. Function 1 was not tested because it carries the DualSense.
This fork keeps the original function-0 selection. It does not detach Sony's
driver, take over function 1, reset the chip, upload Bluetooth firmware, or claim
that accepting scan commands proves an operational radio.

If the whole-event receive change still produces zero reports, the next step is
a console trace of USB completion sizes and LE events, followed by investigation
of Sony's per-function routing/ownership. A software-only simulation cannot
choose a safe replacement interface or establish those firmware details.

The existing USB device selection still assumes `/dev/ugen0.2`. A different
console layout may need discovery work. The user profile/virtual DualSense stage
is a separate possible 13.60 blocker after Bluetooth pairing succeeds.

## Host validation

On November 2, 2026, all 14 host test programs passed in WSL. The sanitizer
run passed 200,000 malformed inputs and the LE regression suite (including
30/30 packet-loss runs). The original USB receiver fails the new whole-event
regression; the modified receiver passes. The ELF builds with SDK v0.45 and
Clang 18 using warnings as errors, and neither its dynamic imports nor the
launcher object contain an unresolved `sceAppInstUtilAppInstallTitleDir`.

`make test` includes existing Classic/LE pairing, crypto, profiles, USB descriptor,
web, virtual-pad stubs, rest and instance-lock tests. Added cases cover:

- missing/present launcher export with no file writes when it is absent;
- the production USB transport against stub ioctls, delivering 44-, 68- and
  257-byte events through a 16-byte endpoint without splitting the request;
- Elite Series 2 Secure Connections, GATT input and bonded reconnection with
  private addresses, split/padded advertising fields and batched reports;
- a refused scan followed by recovery, lost scan acknowledgement, a silent
  radio, absence of repeated enables after acknowledgement, and stop cleanup;
- rejected scan parameters, and configuration of Classic discovery;
- rejection of orphan, expired, wrong-address-type and truncated scan responses.

`make fuzz` runs malformed input through the parsers with ASan and UBSan.
The simulated P-256 operation is an upstream stand-in, not cryptographic device
proof. Host tests do not exercise Sony's USB driver or physical paddles.

## Later console test

1. Stop any other controller bridge. Keep a working DualSense and a USB data
   cable available. Load this ELF manually; do not autoload an untested build.
2. Open `http://<ps5-ip>:8095/`. On 13.60 the media-row launcher may be absent.
3. Select Pair, then hold the Elite Series 2 pairing button until it blinks fast.
4. Save `/data/padbridge/padbridge.log` and its `.1` rotation if present. Record
   the PS5 model, firmware, Xbox controller firmware, and whether scanning,
   pairing, virtual-user assignment and actual input each succeeded.
5. Verify sticks, triggers, buttons, the controller's saved paddle mappings and
   rumble in a game, then disconnect/reconnect. Rest mode is a separate test.
6. Stop using the web menu before replacing the ELF. Do not delete `pads.db` as
   a routine recovery step: it contains the saved pairing keys. Review logs for
   controller addresses before sharing them publicly.
